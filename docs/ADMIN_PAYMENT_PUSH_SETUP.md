# Malachite — admin payment push setup

## What the recovered migration configures

The candidate migration `20261126250000_reconcile_admin_payment_push_dispatch.sql` recreates the verified production schema and server path:

- Private, RLS-enabled `admin_push_queue` and `admin_push_subscriptions` tables. No browser policies; only `service_role` has table privileges.
- An insert trigger on `paiements` that queues a payment and requests a signed push.
- A five-minute fallback `pg_cron` job that drains the queue only when pending notifications and an active device subscription exist.
- A service-role-only RPC that returns VAPID and hook secrets from Vault.
- A random internal hook token created in Vault if absent.
- An environment-specific project URL read from Vault. The migration does not hard-code the production endpoint, so staging cannot call production accidentally.

The notification only tells the administrator to review a payment. It does not approve the payment or activate an entitlement.

## Required Vault values

VAPID public/private keys are intentionally not committed to Git and are not generated by the migration. Generate them on a trusted computer:

```sh
npx web-push generate-vapid-keys --json
```

Store the resulting public key as Vault secret `malachite_vapid_public` and private key as `malachite_vapid_private` through the Supabase Dashboard/Vault workflow. Do not paste either key into ChatGPT, GitHub, source files, or logs. The migration creates `malachite_push_hook` separately; do not replace it with a public value.

Also store the current project's base API URL in Vault as `malachite_push_project_url`, for example `https://<PROJECT_REF>.supabase.co`. Use the staging URL in staging and the production URL only in production. Do not include a path or trailing endpoint; the migration appends `/functions/v1/malachite-admin-push`. This URL is environment-specific and is deliberately not auto-created by the migration.

## Verification after deployment

1. Confirm the migration is applied and the five-minute cron job is active.
2. Confirm `malachite_push_project_url` points to the same Supabase project as the database running the migration.
3. Register the administrator's device from Malachite's Admin push settings.
4. Use the Admin **test notification** action and confirm delivery on that device.
5. Submit a test payment only in an isolated environment; verify the push says it needs review and does not change payment status.
6. Confirm queue drain removes a delivered item and retains it when no device is registered or delivery fails.

No real payment should be submitted solely to test push delivery on production.
